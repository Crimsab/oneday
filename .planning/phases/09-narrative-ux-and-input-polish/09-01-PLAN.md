# Plan 09-01: Turn-Flow Reliability + Resume/Choice Lifecycle Fixes

**Phase:** 9 — Narrative UX and Input Polish
**Wave:** 1 — runtime correctness first
**Requirements:** STOR-06, TUI-17, TUI-20, TUI-21

---

## Objective

Fix the correctness issues that make the narrative view feel unstable: synthetic resume text, stale or duplicated choices, literal escaped newlines, and invalid vital values. This wave must make the next-turn interaction state trustworthy before we polish the visuals.

## Tasks

### Task 1: Rebuild resume from local persisted turn data instead of synthetic fallback
**Files:**
- `internal/engine/narrator.go`
- `internal/engine/session.go`
- `internal/storage/chat.go`
- `internal/engine/types.go`

**Action:**
- Stop treating the last assistant DB message as if it were raw structured JSON.
- Use persisted local narrative text plus stored metadata to reconstruct the last visible turn when resuming.
- Persist richer assistant metadata going forward so future resumes can recover choices, mood, location, dialogue/callout/ascii metadata, and similar renderer-facing details without a new AI call.
- Keep the synthetic fallback only as a last resort when no meaningful local turn exists.

**Verify:**
- resuming a recent story does not trigger a new AI request
- resume shows the actual last turn text instead of a generic "Welcome back..." message whenever local data exists

### Task 2: Sanitize and stabilize choice lifecycle
**Files:**
- `internal/engine/narrator.go`
- `internal/tui/views/narrative.go`
- `internal/tui/views/narrative_choices.go`
- `internal/tui/components/choicelist.go`

**Action:**
- sanitize incoming choices before rendering:
  - remove blank items
  - dedupe repeated text
  - renumber UI-visible IDs sequentially
- ensure selected choices disappear immediately while the next turn is being prepared
- prevent duplicate/stale rows from surviving across streamed turns or resume restoration

**Verify:**
- malformed/duplicate AI IDs do not produce repeated `1.` rows
- once a choice is selected, the old list does not remain on screen while waiting

### Task 3: Normalize escaped newlines and resume rendering behavior
**Files:**
- `internal/engine/narrator.go`
- `internal/tui/views/narrative.go`

**Action:**
- normalize literal escaped newline artifacts in final narrative text and dialogue block text
- adjust resume rendering so it restores the prior turn cleanly without making it look like the story is auto-playing behind the choice list

**Verify:**
- literal `\\n\\n` sequences no longer leak into the narrative body in normal play
- resume feels like restoration, not a new streaming turn

### Task 4: Clamp vitals to valid ranges
**Files:**
- `internal/engine/state.go`
- `internal/tui/components/statusbar.go`

**Action:**
- clamp character vitals to `0 <= current <= max`
- keep footer rendering stable when malformed state data exists

**Verify:**
- values like `55/50` no longer persist after state application

### Task 5: Add focused regression tests for resume and choices
**Files:**
- `internal/tui/views/narrative_choices_test.go`
- `internal/tui/views/narrative_streaming_test.go`
- `internal/engine/rendering_test.go`

**Action:**
- cover resume reconstruction from local metadata
- cover choice sanitization and stale-choice clearing
- cover newline normalization and vital clamping edge cases where appropriate

**Verify:**
- `go test ./...` passes with targeted regressions covered
