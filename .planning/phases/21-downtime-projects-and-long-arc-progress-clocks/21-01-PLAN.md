# Plan 21.1: Canonical Project Clocks

## Goal

Turn downtime from one-off flavor scenes into persistent, player-owned long-arc projects with canonical progress.

## Tasks

1. Define project-clock models for training, rituals, crafting lines, relationship arcs, and safehouse/base improvements.
2. Support starting, pausing, resuming, and completing projects across multiple downtime opportunities.
3. Persist project state so it survives save/load and can be inspected outside the moment a downtime scene occurs.
4. Keep project clocks expressive enough for many project types without hardcoding each one as a separate subsystem.

## Verification

- long-arc projects persist as canonical state instead of ephemeral scene notes
- projects can be resumed over time instead of restarting every downtime scene
- one model can support multiple project categories cleanly
