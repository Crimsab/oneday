# OneDay — Roadmap

## v0.1 — Foundation

The minimum to play a basic story.

- [ ] Project setup (Go module, dependencies, build)
- [ ] Global config system (`config.yaml`)
- [ ] SQLite storage layer (connection, migrations, CRUD)
- [ ] AI client with provider router (Claude Code → LiteLLM → OpenRouter fallback)
- [ ] TUI shell: Bubbletea app with navigation, views, theme
- [ ] Main menu (new story, load story, settings, quit)
- [ ] Story creation flow (AI asks questions, builds story.json collaboratively)
- [ ] Character creation (name + optional background)
- [ ] Core narrative loop:
  - Input (choices + free action always available) → context builder → AI call → parse response → state update → render
- [ ] Chat history persistence (JSONL per session)
- [ ] Session management (auto-create on play, save on exit)
- [ ] Save/load system (autosave + manual saves)
- [ ] Status bar (vitals + AI model + latency)
- [ ] Streaming AI responses (typewriter effect)

## v0.2 — Depth

Making the game actually interesting.

- [ ] NPC system (generated at runtime, personality, private thoughts, notes, desires)
- [ ] Relationship tracking (disposition, history)
- [ ] RAG system:
  - Embedding generation (text-embedding-3-small via LiteLLM)
  - sqlite-vec storage and retrieval
  - Periodic summarization (every N turns → chunk)
  - Context builder uses RAG for relevant history
- [ ] Chapter system (AI determines chapter boundaries, generates summaries)
- [ ] Stat checks (passive, threshold-based)
- [ ] Dice rolls (active, with modifiers from stats/skills/items, TUI animation)
- [ ] Inventory system (backpack, equipped, quest items)
- [ ] Skill system (learn by doing, XP, levels, specializations — all AI-defined)
- [ ] Attribute growth (slow, use-based, AI-suggested)
- [ ] Trait emergence (AI observes patterns, assigns traits)
- [ ] Title system (AI awards based on deeds)

## v0.3 — Systems

Major gameplay systems.

- [ ] Combat system:
  - Turn-based, separate chat session
  - Enemy generation (stats, behavior patterns)
  - Damage calculation (engine-side, not AI)
  - Free action always available (talk, flee, creative solutions)
  - Defeat handling (AI decides: death/capture/rescue/unconscious/retreat)
  - Combat summary written to main narrative after resolution
- [ ] Crafting system:
  - Conversation-based, separate chat session
  - AI evaluates feasibility (materials + world rules + skills)
  - Items with narrative effects (no numerical stats)
  - Recipe discovery and memory
- [ ] Mini-games:
  - Rock-paper-scissors
  - Dice gambling
  - Memory sequences
  - Quick-time events (timed key press)
  - Riddles (AI-generated)
- [ ] Conditions/status effects (poisoned, blessed, exhausted — AI-managed)
- [ ] Currency and trading (with NPCs)

## v0.4 — Polish

Quality of life and depth.

- [ ] Achievement system (AI-driven, category-based rules, per-story)
- [ ] ASCII art (strategic, AI-generated inline for key moments)
- [ ] Undo/rewind (go back N turns, branch the story)
- [ ] Story branching visualization (tree of key decisions)
- [ ] World map (ASCII, generated by AI as locations are discovered)
- [ ] Player journal (automatic + manual entries)
- [ ] Character sheet view (full stats, skills, relationships, titles)
- [ ] Improved NPC dialogue (dedicated dialogue sessions)
- [ ] Mood-based theming (Lipgloss styles change with narrative mood)
- [ ] Story export (full narrative as markdown)

## v0.5 — Expansion

Advanced features.

- [ ] Plugin system phase 1: custom stories via JSON/YAML
- [ ] Plugin system phase 2: Lua scripting (gopher-lua)
- [ ] Plugin hooks (on_combat_start, on_npc_interact, etc.)
- [ ] Plugin discovery and loading
- [ ] Cross-compilation CI (Windows, Linux, macOS binaries)
- [ ] Multiple save slots per story
- [ ] Story gallery (browse, filter, search saved stories)
- [ ] AI model benchmarking (compare quality/speed across models for your stories)

---

## Principles

- Ship each version as a playable game. Don't wait for v0.5 to play.
- Nothing hardcoded. If it can be AI-generated, it should be.
- Modularity: each system is a package with clean interfaces.
- The engine resolves mechanics. The AI resolves narrative.
