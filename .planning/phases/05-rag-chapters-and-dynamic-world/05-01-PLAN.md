# Plan 5.1: Embedding Client, Vector Storage, and Periodic Summarization

## Objective

Build the complete RAG infrastructure: an embedding client that calls text-embedding-3-small via LiteLLM, a vector store that persists embeddings in SQLite as BLOBs with brute-force cosine similarity (no sqlite-vec dependency — pragmatic approach for <10K vectors per story), and a summarization engine that periodically condenses N turns into embedded chunks. Integrate with the context builder so top-K relevant chunks are injected into AI prompts.

## Key Decisions

- **No sqlite-vec**: sqlite-vec Go bindings require CGO; our project uses `modernc.org/sqlite` (pure Go). Brute-force cosine similarity in Go is fast enough for <10K vectors per story (typical: 100-500 vectors even after hundreds of hours of play).
- **Embedding via LiteLLM**: Reuse the existing OpenAI-compatible provider infrastructure. The embedding endpoint is `/v1/embeddings` on the same base URL.
- **Storage**: Embeddings stored as BLOB ([]float32 serialized to binary) in a regular SQLite table. No separate embeddings.db file — same database, new table.
- **Summarization trigger**: After every N turns (config `rag.summarize_every`, default 10), the narrator triggers summarization of the unsummarized turns. This happens asynchronously after the turn response.
- **Dimensions**: text-embedding-3-small produces 1536-dimensional vectors (configurable in config).

## Verification

- [ ] Embedding client can call LiteLLM `/v1/embeddings` and return float32 vectors
- [ ] Vector store can insert and retrieve embeddings with cosine similarity ranking
- [ ] Summarizer condenses N turns into a text chunk and embeds it
- [ ] After N turns, summarization fires automatically
- [ ] Context builder retrieves top-K chunks and injects them into AI prompt
- [ ] RAG chunks appear in the "Relevant Memory" section of the AI context
- [ ] Existing gameplay is not broken (RAG is additive, not disruptive)

```go
package rag

import (
    "database/sql"
    "encoding/binary"
    "math"
)

// VectorStore manages embedding storage and retrieval in SQLite.
type VectorStore struct {
    db *sql.DB
}

// Chunk represents a stored text chunk with its embedding.
type Chunk struct {
    ID        int64
    StoryID   string
    Text      string
    ChunkType string  // "summary", "narrator", "chapter"
    TurnStart int
    TurnEnd   int
    Embedding []float32
    CreatedAt time.Time
}

// SearchResult is a chunk with its similarity score.
type SearchResult struct {
    Chunk      Chunk
    Similarity float64  // cosine similarity, 0.0 to 1.0
}

func NewVectorStore(db *sql.DB) *VectorStore

// Insert stores a chunk with its embedding.
func (vs *VectorStore) Insert(ctx context.Context, chunk *Chunk) error

// Search returns the top-K most similar chunks to the query embedding.
func (vs *VectorStore) Search(ctx context.Context, storyID string, queryEmbedding []float32, topK int) ([]SearchResult, error)

// CountByStory returns the number of chunks for a story.
func (vs *VectorStore) CountByStory(ctx context.Context, storyID string) (int, error)

// LastSummarizedTurn returns the highest turn_end for summary chunks of a story.
func (vs *VectorStore) LastSummarizedTurn(ctx context.Context, storyID string) (int, error)
```

**Cosine similarity** implemented in pure Go:
```go
func cosineSimilarity(a, b []float32) float64 {
    var dot, normA, normB float64
    for i := range a {
        dot += float64(a[i]) * float64(b[i])
        normA += float64(a[i]) * float64(a[i])
        normB += float64(b[i]) * float64(b[i])
    }
    if normA == 0 || normB == 0 {
        return 0
    }
    return dot / (math.Sqrt(normA) * math.Sqrt(normB))
}
```

**Embedding serialization** — store as BLOB (binary float32):
```go
func serializeEmbedding(v []float32) []byte {
    buf := make([]byte, len(v)*4)
    for i, f := range v {
        binary.LittleEndian.PutUint32(buf[i*4:], math.Float32bits(f))
    }
    return buf
}

func deserializeEmbedding(b []byte) []float32 {
    v := make([]float32, len(b)/4)
    for i := range v {
        v[i] = math.Float32frombits(binary.LittleEndian.Uint32(b[i*4:]))
    }
    return v
}
```

The `Search` method:
1. Load ALL embeddings for the story from DB (they're small: 1536 * 4 bytes = 6KB each)
2. Compute cosine similarity against query embedding
3. Sort by similarity descending
4. Return top-K results

This is O(n) per search but n < 10K so it completes in <10ms even on modest hardware.

```go
// Summarizer periodically condenses turns into embedded chunks.
type Summarizer struct {
    embedder  *Embedder
    store     *VectorStore
    aiRouter  AIProvider  // interface: Complete(ctx, req) (resp, err)
    storyID   string
    interval  int  // summarize every N turns
}

// AIProvider is the interface for AI completion (summarization prompt).
type AIProvider interface {
    Complete(ctx context.Context, req CompletionRequest) (CompletionResponse, error)
}

func NewSummarizer(embedder *Embedder, store *VectorStore, aiRouter AIProvider, storyID string, interval int) *Summarizer

// ShouldSummarize checks if there are enough unsummarized turns.
func (s *Summarizer) ShouldSummarize(ctx context.Context, currentTurn int) (bool, error)

// Summarize generates a summary of unsummarized turns, embeds it, and stores it.
func (s *Summarizer) Summarize(ctx context.Context, messages []storage.ChatMessage, currentTurn int) error
```

**Summarization flow:**
1. `ShouldSummarize`: check `LastSummarizedTurn` vs `currentTurn`. If gap >= interval, return true.
2. `Summarize`:
   a. Get unsummarized messages from the chat DB (turns from lastSummarizedTurn+1 to currentTurn)
   b. Build a summarization prompt:
      ```
      Summarize the following narrative turns concisely. Focus on:
      - Key events and decisions
      - NPC interactions and relationship changes
      - Location changes
      - Items gained/lost
      - Character growth (skills, traits, titles)
      Keep the summary under 500 words. Write in past tense, third person.
      
      [messages concatenated]
      ```
   c. Call AI to generate summary text
   d. Generate embedding for the summary
   e. Store as a Chunk with type "summary", turn_start and turn_end set

The summarization prompt should be in `internal/ai/prompts/summarizer.go` as a constant.
</action>

## Notes

- The brute-force cosine similarity approach is intentionally simple. For a single-player game with <10K vectors, it's faster to iterate than to maintain a separate index. If performance becomes an issue (unlikely), we can add an in-memory index later.
- Summarization is fire-and-forget (goroutine). If it fails, the next trigger will pick up the gap since it checks `LastSummarizedTurn`.
- RAG is purely additive — if the embedding API is down, gameplay continues normally without long-term memory.
