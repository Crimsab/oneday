# Plan 16.2: Committed-Turn Memory Semantics

## Goal

Fix RAG summary-window semantics so memory indexing is based on committed turns and never skips, duplicates, or delays the first valid summary window.

## Tasks

1. Formalize turn numbering semantics at the memory layer, including whether turn `0` is valid and how the first summarizable window is defined.
2. Align summarization triggers with committed turn ownership so async memory work never runs against pre-commit turn numbers.
3. Correct any off-by-one behavior in summary start/end windows, especially around first-turn, first-summary, rewind, and resume boundaries.
4. Add regression coverage for first-summary generation, resumed stories, and rewind/load flows.

## Verification

- the first committed turn is included correctly in memory windows
- summary windows neither skip nor duplicate turns across resume/rewind
- committed-turn timing, not optimistic pre-increment state, drives memory indexing
