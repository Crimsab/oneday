# Plan 22.4: Release Gates and Operator Workflow Hardening

## Goal

Tighten the local and CI release flow so shipping stale binaries or unverified artifacts becomes much harder.

## Tasks

1. Align README, Makefile, and release workflows on the same required verification steps and artifact expectations.
2. Add a lightweight pre-release checklist or scripted guard that catches stale binaries, missing verification, or out-of-date local assumptions.
3. Document the recommended local shipping flow clearly, including when rebuilds are required and how to confirm the active binary version.
4. Make the release path reinforce the new provenance and smoke-check work instead of bypassing it.

## Verification

- local and CI release guidance no longer disagree about the required steps
- there is a clear release gate for build freshness and verification status
- operators can follow one documented flow to rebuild, verify, and ship safely
