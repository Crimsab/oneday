# Plan 3.1: Session Management, JSONL Chat Persistence, and Context Builder

## Objective

Build the infrastructure layer that Phase 3 depends on: (1) session lifecycle management — auto-create a session when a story opens, track turns, close on exit; (2) JSONL chat persistence — every turn is appended to a JSONL file on disk, with DB-backed metadata; (3) a context builder that assembles the AI prompt from system prompt + recent N chat messages + player state + NPC state + a placeholder slot for RAG chunks. After this plan, the narrator engine uses the context builder for every AI call and all turns are persisted.

## must_haves

- Session auto-created (DB row + filesystem directory) when player opens a story
- Session closed (end time set) when player leaves the narrative view or quits
- Each turn (player input + AI output + metadata) appended to a JSONL file at `{data_dir}/stories/{story_id}/sessions/{session_id}/main.jsonl`
- Context builder assembles: system prompt + last N messages from JSONL + current character stats + current world state
- Context builder has a placeholder slot for RAG chunks (empty slice for now, wired in Phase 5)
- Narrator engine uses context builder instead of maintaining in-memory message history
- On re-entering a story, the most recent open session is resumed (or a new one created)
- Session metadata stored in DB `sessions` table (already exists in schema)

### Task 3: Implement JSONL file writer for chat persistence

Create `internal/engine/session.go` with:

```go
// ChatEntry is the JSONL format for a single turn on disk.
type ChatEntry struct {
    Turn      int        `json:"turn"`
    Timestamp time.Time  `json:"timestamp"`
    Chapter   int        `json:"chapter"`
    Location  string     `json:"location"`
    Input     *ChatInput `json:"input,omitempty"`
    Output    *ChatOutput `json:"output,omitempty"`
    AIModel   string     `json:"ai_model,omitempty"`
    AILatency int64      `json:"ai_latency_ms,omitempty"`
}

type ChatInput struct {
    Type string `json:"type"` // "free_action", "choice", "command"
    Text string `json:"text"`
}

type ChatOutput struct {
    Narrative string   `json:"narrative"`
    Choices   []string `json:"choices,omitempty"`
    Mood      string   `json:"mood,omitempty"`
}

// GameSession manages a play session's lifecycle and JSONL persistence.
type GameSession struct {
    session    *storage.Session
    storyID    string
    dataDir    string
    jsonlFile  *os.File
    turn       int
}

// NewGameSession creates or resumes a session.
// If an active session exists, resumes it. Otherwise creates a new one.
func NewGameSession(db *storage.DB, storyID, dataDir string) (*GameSession, error)

// AppendTurn writes a ChatEntry to the JSONL file AND inserts into DB.
func (gs *GameSession) AppendTurn(db *storage.DB, entry ChatEntry) error

// Close flushes the JSONL file and closes the session in DB.
func (gs *GameSession) Close(db *storage.DB) error

// SessionID returns the session ID.
func (gs *GameSession) SessionID() string

// Turn returns the current turn number.
func (gs *GameSession) Turn() int
```

**NewGameSession behavior:**
1. Check `db.GetActiveSession(storyID)` — if one exists, resume it.
2. Otherwise, create a new `storage.Session` with `uuid.New()`, `StartedAt: time.Now()`.
3. Create directory `{dataDir}/stories/{storyID}/sessions/{sessionID}/` with `os.MkdirAll`.
4. Open `main.jsonl` with `os.OpenFile(..., os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)`.
5. Count existing lines to set initial turn number (for resume).

**AppendTurn behavior:**
1. Marshal `ChatEntry` to JSON, append `\n`, write to file.
2. Also call `db.AppendChatMessage(...)` with the appropriate fields split into user + assistant messages.
3. Increment turn counter.
</action>

<acceptance_criteria>
- `NewGameSession` creates session directory and `main.jsonl` file
- Resuming an existing session appends to the same JSONL file
- `AppendTurn` writes valid JSONL (one JSON object per line)
- `Close` sets `ended_at` in DB and closes the file handle
</acceptance_criteria>

```go
// ContextConfig controls how the context builder assembles prompts.
type ContextConfig struct {
    RecentMessageCount int      // how many recent messages to include (default 20)
    RAGChunks          []string // placeholder for Phase 5 RAG — empty for now
}

// DefaultContextConfig returns sensible defaults.
func DefaultContextConfig() ContextConfig {
    return ContextConfig{
        RecentMessageCount: 20,
        RAGChunks:          nil,
    }
}

// BuildContext assembles the full message list for an AI call.
// Order: [system prompt, ...recent messages, current user input]
func BuildContext(
    story *storage.Story,
    char *storage.Character,
    world *storage.WorldState,
    recentMessages []storage.ChatMessage,
    ragChunks []string,
    currentInput string,
) []ai.Message
```

**BuildContext logic:**
1. Build system prompt using `prompts.NarratorSystem(...)` — same as today.
2. Add a "state summary" system message with current character stats, world state, location, chapter, turn. This is separate from the initial system prompt so it reflects current state, not creation-time state.
3. If `ragChunks` is non-empty, add a system message: `"## Relevant Memory\n" + strings.Join(ragChunks, "\n---\n")`.
4. Convert `recentMessages` to `[]ai.Message` — map `ChatMessage.Role` to `ai.RoleUser`/`ai.RoleAssistant`.
5. Append the current user input as the final user message.
6. Return the assembled slice.

**Update `prompts.NarratorSystem`** to accept a new parameter `currentStatsJSON string` (the live stats, not the creation-time stats). The existing prompt already takes `charStatsJSON` — rename it to clarify it's the live stats. This is a signature-only change; the prompt content stays the same.
</action>

<acceptance_criteria>

- RAG slot accepts `[]string` but works correctly when nil/empty
- System prompt includes up-to-date character stats (not stale creation-time stats)
</acceptance_criteria>
