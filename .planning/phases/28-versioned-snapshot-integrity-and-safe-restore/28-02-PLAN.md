# Plan 28.2: Explicit Legacy and Corruption Policies

## Objective

Route snapshot validation outcomes through load behavior and user-facing
contracts so compatibility remains possible without misrepresenting safety.

## Tasks

1. Write failing load tests for missing files, invalid JSON, checksum mismatch, incompatible version, incomplete manifests, and intentional legacy partial loads.
2. Introduce typed snapshot validation/load errors and an explicit legacy policy/result contract.
3. Prevent `loadSaveSnapshot` and `LoadGame` from silently merging DB rows into a corrupt or incomplete full snapshot.
4. Surface actionable legacy/corruption status through TUI and gateway responses without exposing filesystem internals.
5. Add regression tests for each surface contract and for old valid saves.

## Acceptance

- SNAP-02 and SNAP-05 are enforced by behavior, not only documentation.
- A user can distinguish legacy compatibility from a verified full rollback.
- Corrupt/incompatible snapshots leave current canonical state untouched.
