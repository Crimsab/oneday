# Plan 22.1: Build Identity and Runtime Provenance

## Goal

Make every built binary clearly identify itself so stale local builds and release artifacts are obvious at runtime.

## Tasks

1. Add compile-time build metadata such as version, commit, build date, and dirty-state markers where appropriate.
2. Surface that build identity through operator-facing paths like `--version`, startup/help output, or other lightweight runtime affordances.
3. Ensure local build commands and release workflows stamp the same metadata consistently instead of producing anonymous binaries.
4. Verify a developer can quickly tell whether `./oneday` matches the current source tree before testing or shipping.

## Verification

- running binaries expose enough provenance to distinguish fresh builds from stale ones
- local and CI/release builds stamp metadata in a consistent way
- checking the active build no longer requires guessing from file timestamps alone
