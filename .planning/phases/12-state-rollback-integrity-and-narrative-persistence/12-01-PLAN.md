# Plan 12.1: Full Rollback Snapshot Integrity

## Goal

Turn save/load into a real rollback mechanism that restores the same AI-visible story state the player had when the snapshot was created.

## Tasks

1. Expand save snapshots on disk to capture story metadata, NPCs, achievements, chapters, story chat history, sessions, RAG chunks, combat logs, and session JSONL files alongside character/world state.
2. Change load flow so it restores the snapshot from disk, rewinds canonical DB state for the story, and restores session files coherently instead of only rehydrating character/world.
3. Keep save metadata in SQLite for listing/deleting saves, but make rollback fidelity come from the on-disk snapshot payload.
4. Handle legacy saves explicitly so pre-upgrade snapshots degrade predictably instead of pretending to be full rollbacks.

## Verification

- loading a recent save rewinds canonical story history instead of mixing in newer turns
- restored sessions/chat messages/RAG chunks match the snapshot rather than the latest global story state
- session JSONL files no longer retain “future” turns after a load
- legacy saves still load, but are detectable as partial rollbacks
