# Plan 08-02: Semantic Choice Rendering + Narrative Integration Polish

**Phase:** 8 — TUI Rendering Polish
**Wave:** 2 — choices + integration + verification
**Requirements:** AI-06, TUI-13, TUI-14

---

## Context

Wave 1 establishes the renderer contract and narrative foundations. Wave 2 focuses on the most decision-facing part of the narrative loop: the suggested choices. The rendering notes explicitly call out semantic choice rendering as a major follow-up item, but with guardrails:

- it must be story-agnostic
- it must not hardcode stat vocabularies
- it must stay readable in long sessions
- it must fall back cleanly when metadata is absent

This wave also closes the loop with renderer verification and narrative-view integration polish.

## Objective

Extend the new renderer contract into the choice system so suggested actions can expose semantic intent/risk metadata and optional story-schema stat badges without sacrificing keyboard flow, readability, or fallback safety.

## Tasks

### Task 1: Extend the choice contract end-to-end
**Files:**
- `internal/engine/types.go`
- `internal/ai/response.go`
- `internal/ai/prompts/narrator.go`
- `internal/tui/components/choicelist.go`

**Action:**
Thread optional semantic choice metadata through the whole stack:
- `intent`
- `risk`
- `scope`
- `certainty`
- `related_stats`

The narrator prompt should describe these as optional guidance fields rather than mandatory output on every turn.

**Verify:**
- choice parsing works with and without metadata
- old responses with plain choices remain valid

### Task 2: Resolve dynamic stat badges from the active story schema
**Files:**
- `internal/tui/views/narrative.go`
- `internal/tui/components/choicelist.go`
- `internal/engine/context.go`

**Action:**
Build helpers that resolve `related_stats` keys into player-facing labels using the current story's `stats_schema`.

Rules:
- use current story schema only
- preserve order from AI metadata where possible
- ignore unknown stat keys safely

Result:
- a choice like `related_stats: ["cha", "wil"]` becomes badges using current story labels, not hardcoded assumptions

**Verify:**
- custom schema labels render correctly
- unknown keys are skipped without noise

### Task 3: Upgrade the choice list component for semantic rendering
**Files:**
- `internal/tui/components/choicelist.go`
- `internal/tui/theme/theme.go`
- `internal/tui/theme/mood.go`

**Action:**
Render semantic metadata in a lightweight, readable form:
- intent indicator
- risk label/badge
- optional certainty marker
- optional related stat badges

Guardrails:
- no color-only meaning
- preserve number keys and keyboard flow
- if metadata is missing, render exactly like the current simple choice list

**Verify:**
- keyboard interaction is unchanged
- plain and enriched choices can coexist in one list

### Task 4: Integrate choice rendering with the narrative renderer and mood system
**Files:**
- `internal/tui/views/narrative.go`
- `internal/tui/components/choicelist.go`
- `internal/tui/theme/mood.go`

**Action:**
Make semantic choices feel integrated with the rest of the narrative polish:
- subtle mood-aware accenting when appropriate
- alignment with event callouts and speaker-rendered prose
- no heavy recoloring of the main narrative body

This is an integration pass, not a redesign.

**Verify:**
- choices remain readable across neutral, tense, dark, peaceful, and epic moods
- mood accents support, rather than overpower, semantic badges
