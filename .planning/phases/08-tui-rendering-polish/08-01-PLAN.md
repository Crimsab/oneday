# Plan 08-01: Rendering Contract + Narrative Semantic Renderer Foundation

**Phase:** 8 — TUI Rendering Polish
**Wave:** 1 — contract + narrative foundations
**Requirements:** AI-06, TUI-10, TUI-11, TUI-12, TUI-14

---

## Context

The current narrative experience is still mostly `markdown -> viewport -> typewriter` plus a simple choice list. That is functional, but it does not yet deliver the narrative rendering polish captured in `.planning/TUI_RENDERING_NOTES_2026-04-08.md`.

The key missing layer is a dedicated semantic renderer contract between AI/runtime output and the TUI. Without that layer, speaker styling, known-entity highlighting, and event callouts would devolve into brittle heuristics inside `narrative.go`.

Phase 6.1 already stabilized the state/persistence baseline and Phase 7 already delivered mood theming + achievement popup. Phase 8 should therefore focus on the narrative renderer itself, not re-open old persistence work or add unrelated systems.

## Objective

Create the renderer-facing data contract and the narrative semantic rendering foundation needed for speaker-aware prose, trusted entity highlighting, and event callouts, while preserving safe fallback behavior when metadata is absent.

---

## Tasks

### Task 1: Extend the narrative response contract with optional rendering metadata
**Files:**
- `internal/engine/types.go`
- `internal/ai/response.go`
- `internal/ai/prompts/narrator.go`

**Action:**
Add optional, backwards-compatible metadata that the renderer can consume when available:

- enrich `Choice` with optional semantic metadata:
  - `intent`
  - `risk`
  - `scope`
  - `certainty`
  - `related_stats`
- add optional narrative metadata types such as:
  - `DialogueBlock`
  - `EntityMention`
  - `EventCallout`
  - optional `scene_type` or equivalent lightweight scene classifier
- keep all new fields optional so the game remains compatible with old saves/responses and any provider that omits them

**Important constraints:**
- no story-specific stat assumptions
- no hard requirement that the AI must emit these fields every turn
- response parsing must remain safe if the metadata is absent, partial, or malformed

**Verify:**
- `go build ./...` passes
- parsing tests cover omission and presence of the new fields

### Task 2: Introduce a dedicated narrative semantic renderer layer
**Files:**
- `internal/tui/rendering/narrative.go` (new)
- `internal/tui/rendering/types.go` (new)
- `internal/tui/views/narrative.go`

**Action:**
Create an explicit renderer subsystem instead of scattering behavior directly in `narrative.go`.

The renderer should accept:
- raw narrative text
- optional dialogue blocks
- optional entity mentions
- optional event callouts
- known entity/state inputs from runtime

It should output render-ready sections for:
- prose/dialogue blocks
- highlightable entity spans or rendered tokens
- compact event callouts
- safe fallback plain text when metadata is missing

**Verify:**
- renderer package compiles independently
- `narrative.go` uses the renderer as a boundary, not as a pile of ad-hoc styling logic

### Task 3: Implement speaker-aware narrative rendering
**Files:**
- `internal/tui/rendering/narrative.go`
- `internal/tui/views/narrative.go`
- `internal/tui/theme/theme.go`

**Action:**
Render distinct presentation for:
- narrator prose
- NPC speech
- player/meta voice
- system-like/meta narrator content

Rules:
- speaker name and body should be visually distinct
- do not over-style the body copy
- if dialogue metadata is absent, preserve current readable markdown rendering

**Verify:**
- known dialogue blocks render differently by role
- plain unstructured narrative still renders safely

### Task 4: Highlight known entities using persisted state and structured metadata
**Files:**
- `internal/tui/rendering/narrative.go`
- `internal/tui/views/narrative.go`
- `internal/storage/models.go`
- `internal/engine/context.go`

**Action:**
Support lightweight highlighting for entities the system actually knows:
- NPCs
- locations
- factions
- items
- learned skills
- titles
- chapter names

Sources of truth:
- persisted DB/state models
- structured metadata from the AI/runtime

Do not:
- color arbitrary words
- depend on loose regex-only heuristics as the primary mechanism

**Verify:**
- stored entity names can render with consistent highlight treatment
- unknown words remain plain text

### Task 5: Build the event callout pipeline from engine-tracked state changes
**Files:**
- `internal/engine/narrator.go`
- `internal/engine/state.go`
- `internal/tui/rendering/narrative.go`
- `internal/tui/views/narrative.go`

**Action:**
Convert important game events into compact, renderer-friendly callouts.

Primary source:
- `ApplyStateChanges()` return value (`[]StateChange`)

Candidate callout categories:
- new NPC encountered
- new location discovered
- world event recorded
- faction standing changed
- skill learned / XP gained
- trait gained
- title earned
- item acquired / lost
- recipe discovered

These callouts should be rendered separately from the prose body and should remain compact.

**Verify:**
- callouts are stable and deterministic in order
- no duplicate or spammy callouts for the same event in one turn

### Task 6: Define strong fallback behavior for partial metadata
**Files:**
- `internal/tui/rendering/narrative.go`
- `internal/tui/views/narrative.go`
- `internal/ai/prompts/narrator.go`

**Action:**
Codify fallback rules for all new metadata:
- no metadata -> current plain rendering path
- missing `related_stats` -> semantic choices without stat badges
- unknown entity metadata -> plain text, no broken markup
- malformed dialogue blocks -> ignore the block, keep raw narrative
- conflicting callouts -> prefer engine-tracked data over prose-derived guesses

**Verify:**
- gameplay never depends on renderer metadata being present
- renderer failures degrade to readable output rather than blocking the loop

### Task 7: Add renderer-focused tests
**Files:**
- `internal/tui/rendering/narrative_test.go` (new)
- `internal/ai/response_test.go`
- `internal/engine/state_test.go` (only if additional callout helpers need coverage)

**Action:**
Add focused tests for:
- speaker-aware rendering
- entity highlighting for known names
- event callout ordering and stability
- omission/fallback behavior
- malformed metadata behavior

Prefer stable, snapshot-like assertions where useful, but keep them maintainable and text-oriented.

**Verify:**
- `go test ./...` passes with the new renderer tests
