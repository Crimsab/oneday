# Plan 22.3: Cross-System QA Matrix and Failure Sweep

## Goal

Exercise the multi-turn, cross-system interactions that automation still misses and turn that sweep into a reusable QA checklist.

## Tasks

1. Build a manual QA matrix that covers long-play and mixed-system scenarios such as rewind branches, legacy save loading, fronts plus investigations, projects plus pressure, and social-duel aftermath.
2. Run the matrix locally against the updated binary and record concrete reproduction notes for any failures, rough edges, or confusing operator flows.
3. Fix the highest-confidence defects found during the sweep or document them with severity, impact, and next action if they should be deferred.
4. Re-run impacted checks after fixes so the phase ends with a validated matrix rather than a one-pass bug hunt.

## Verification

- the project has a reusable QA matrix for high-risk integrated flows
- issues found during the sweep are either fixed or explicitly triaged
- post-fix verification confirms the swept flows still hold together
