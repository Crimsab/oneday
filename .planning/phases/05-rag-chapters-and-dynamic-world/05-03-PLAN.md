# Plan 5.3: /map, /journal, /achievements Commands + Dynamic World Updates + Context Builder Integration

## Objective

Complete Phase 5 by implementing the three remaining chat commands (/map, /journal, /achievements), building the dynamic world update system where story.json and NPC data evolve through organic gameplay (not just /narrator), and fully integrating RAG + chapters + world state into the context builder for maximum narrative coherence.

## Key Decisions

- **/map**: Renders discovered locations from `world_state.known_locations_json`. Shows current location highlighted. Text-based list format (ASCII map generation is a v2 feature per ADV-02).
- **/journal**: Shows chapter summaries from the chapter system (Plan 5.2) plus any manually noted entries. Reads from the chapters DB table.
- **/achievements**: Shows earned achievements from the achievements DB table. Already has storage (migrationV1). Display as a formatted list with name, description, rarity, category.
- **Dynamic world updates**: The AI's regular narrative responses can now include world-modifying state_changes (same keys as /narrator: setting updates, location discoveries, faction changes). This makes story.json a living document that grows through play.
- **NPC evolution (WORLD-02)**: After each turn, if an NPC was mentioned, update their private_thoughts and notes_on_protagonist based on the interaction. This already partially works via `npc_thoughts` and `npc_notes` state_changes — ensure it's reliable and the AI uses it consistently.
- **Context builder integration**: Finalize the context assembly order: system prompt + state summary + RAG chunks + chapter context + recent messages + user input.

## Verification

- [ ] /map shows discovered locations with current location highlighted
- [ ] /journal shows chapter summaries in chronological order
- [ ] /achievements shows earned achievements (or "No achievements yet")
- [ ] Story setting auto-updates when AI discovers new factions/locations/dangers during gameplay
- [ ] NPC private_thoughts and notes evolve after interactions
- [ ] World state tracks unlocked locations, global events, faction standings
- [ ] Context builder includes RAG chunks, chapter info, and world state in AI prompts
- [ ] All three commands have short aliases (/m, /j, /a)
- [ ] Help text updated with new commands

## Wave Structure

**Wave 1** (Tasks 1, 4, 8): Independent quick tasks — command registration, achievements display, help text. No dependencies on other tasks.

**Wave 2** (Tasks 2, 3, 5): /map + /journal + dynamic world updates. Task 2 uses world state. Task 3 uses chapters. Task 5 modifies the prompt and auto-tracking. All independent of each other but depend on Plan 5.2 being complete.

**Wave 3** (Tasks 6, 7): NPC evolution audit + context builder finalization. These tie everything together and are the final integration tasks for Phase 5.

## Notes

- /map in this phase is a text list, not an ASCII art map. The ADV-02 requirement (ASCII world map) is v2 scope. The text list is pragmatic and immediately useful.
- /achievements display is built here but achievement *earning* is Phase 7 (ACH-01 through ACH-04). In this phase, the command exists but shows empty until Phase 7 adds the detection logic.
- The context builder refactoring (Task 7) is important for long-term narrative quality. The richer the context, the more coherent the AI's responses. But we must be careful about context window size — the state summary should be concise, not dump raw JSON.
- Dynamic world updates (Task 5) are the key differentiator. When the AI organically discovers a new faction during gameplay, it should automatically update story.json — making the world genuinely evolve through play without the player needing /narrator.
