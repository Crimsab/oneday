# Plan 17.1: Canonical Front State and Engine Events

## Goal

Introduce canonical faction-front state and engine-owned front events so world escalation can persist independently of momentary AI prose.

## Tasks

1. Define a front model that captures faction identity, segments/progress, stakes, visibility, active pressure, timers, and resolution state.
2. Add canonical engine events for front advance, reveal, stall, resolve, and consequence application.
3. Persist fronts in a way that survives save/load, rollback, history reconstruction, and codex inspection.
4. Keep hidden and discovered front information distinct so the player only sees what the game has earned.

## Verification

- fronts persist as canonical state instead of ephemeral prompt text
- front progress and resolution survive save/load and rewind coherently
- hidden-vs-known front information stays separated
