# Plan 22.2: Critical Path Smoke Coverage

## Goal

Cover the highest-risk player flows with fast, repeatable smoke checks that catch regressions before manual QA or release.

## Tasks

1. Define the critical path matrix for the current game state: boot, story entry, save/load/resume, codex browsing, investigations, projects, fronts, and social-duel runtime transitions.
2. Add or extend deterministic automated tests around the engine and TUI boundaries for those flows without depending on live provider behavior.
3. Keep the smoke suite lightweight enough for local iteration while still reflecting real user paths instead of isolated helpers.
4. Ensure failures point clearly to the broken flow so the suite is useful as a pre-release gate, not just a CI checkbox.

## Verification

- the critical flows have automated smoke coverage beyond isolated unit helpers
- the smoke suite runs locally and in CI without external-provider flakiness
- regressions in key runtime flows fail with actionable signals
