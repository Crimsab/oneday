# Plan 6.2: Combat TUI View + Crafting Engine + Crafting TUI View

## Objective

Build the visual layer for combat (HP bars, turn counter, choices + free input) and the complete crafting system (engine + TUI). Crafting is a conversation with the AI in a separate chat session where the player describes what they want to build and the AI evaluates feasibility. No hardcoded recipes — everything is AI-evaluated based on inventory, world rules, and skills.

## Key Decisions

- **Combat TUI is a separate Bubbletea model** (`CombatModel`) that replaces the narrative view during combat. It shares the same input/choice/typewriter patterns but adds HP bars and turn info.
- **Crafting TUI is also a separate model** (`CraftingModel`) with a split view: inventory on the left, conversation on the right.
- **Navigation**: The narrative view detects `CombatStart` in the AI response and transitions to CombatModel. When combat ends, it transitions back with the summary. Same pattern for crafting via a `/craft` command.
- **HP bars**: A reusable `HPBar` component that renders a colored bar with current/max values. Used for both player and enemy HP.
- **Crafting conversation**: Uses the existing sub-session mechanism. Each crafting session is a short AI conversation (typically 2-5 exchanges). The AI evaluates feasibility and either creates an item or explains what's missing.
- **Items have narrative effects**: Crafted items get a `description` and `effect` (both strings). No numerical stat bonuses — the AI interprets item effects narratively during gameplay.

package components

import (
    "fmt"
    "strings"

    "github.com/charmbracelet/lipgloss"
    "github.com/crimsab/oneday/internal/tui/theme"
)

// HPBar renders a horizontal HP bar with label, current/max, and colored fill.
type HPBar struct {
    Label   string
    Current int
    Max     int
    Width   int // total width of the bar in characters
}

// NewHPBar creates an HP bar.
func NewHPBar(label string, current, max, width int) HPBar

// View renders the HP bar.
// Format: "Label: [████████░░░░░░░░] 15/20"
func (h HPBar) View() string
```

**Rendering logic:**
1. Calculate fill percentage: `pct = float64(current) / float64(max)`
2. Bar width = `h.Width - len(label) - len(" XX/XX") - 4` (for brackets and spaces)
3. Fill chars = `int(pct * barWidth)` using `"█"` for filled, `"░"` for empty
4. Color the filled portion:
   - pct > 0.5: green (`theme.Success`)
   - pct > 0.25: yellow/gold (`theme.Accent`)
   - pct <= 0.25: red (`theme.Danger`)
5. Compose: `Label: [colored_fill + empty] current/max`

package engine

import (
    "context"
    "encoding/json"
    "fmt"
    "time"

    "github.com/crimsab/oneday/internal/ai"
    "github.com/crimsab/oneday/internal/ai/prompts"
    "github.com/crimsab/oneday/internal/storage"
)

// CraftedItem represents an item created through crafting.
type CraftedItem struct {
    Name        string   `json:"name"`
    Description string   `json:"description"`  // narrative description
    Effect      string   `json:"effect"`        // what it does (narrative, not numerical)
    Materials   []string `json:"materials"`     // what was consumed to make it
    CraftedAt   string   `json:"crafted_at"`    // timestamp
}

// CraftingResponse is the AI's evaluation of a crafting attempt.
type CraftingResponse struct {
    Feasible     bool        `json:"feasible"`
    Narrative    string      `json:"narrative"`      // AI's description of the attempt
    Item         *CraftedItem `json:"item,omitempty"` // only if feasible
    Missing      []string    `json:"missing,omitempty"` // what player lacks
    Alternatives []string    `json:"alternatives,omitempty"` // what they could make instead
    Choices      []Choice    `json:"choices,omitempty"` // next options
}

// CraftingEngine manages a crafting conversation session.
type CraftingEngine struct {
    narrator     *Narrator
    session      *GameSession
    subSessionID string
    chatHistory  []ai.Message // conversation within this crafting session
    turnCount    int
}

// NewCraftingEngine starts a crafting session.
func NewCraftingEngine(narrator *Narrator) (*CraftingEngine, error)
```

**NewCraftingEngine:**
1. Open sub-session: `narrator.session.OpenSubSession("crafting")`
2. Build initial context with crafting system prompt + character inventory + known recipes
3. Return engine

**Core methods:**

```go
// SendMessage sends a player message in the crafting conversation.
// The player describes what they want to craft or asks about possibilities.
func (ce *CraftingEngine) SendMessage(ctx context.Context, message string) (*CraftingResponse, error)

// Close ends the crafting session.
func (ce *CraftingEngine) Close() error
```

**SendMessage flow:**
1. Append player message to `chatHistory`
2. Build context: crafting system prompt + inventory + known recipes + chatHistory
3. Call AI
4. Parse response as `CraftingResponse`
5. If `response.Feasible` and `response.Item != nil`:
   a. Add item to character inventory (via `state_changes.inventory_add`)
   b. Remove consumed materials (via `state_changes.inventory_remove`)
   c. Save recipe to `known_recipes` (if not already known)
   d. Log crafting in sub-session JSONL
6. Append AI response to `chatHistory`
7. Return response

**Recipe management:**
```go

func (ce *CraftingEngine) SaveRecipe(item *CraftedItem) error

// GetKnownRecipes returns the player's discovered recipes.
func GetKnownRecipes(char *storage.Character) ([]CraftedItem, error)
```

## Notes

- The combat view and crafting view both follow the same pattern as the narrative view: viewport + typewriter + choices + input. This consistency ensures the player's muscle memory works across all modes.
- The crafting view uses a two-column layout which is new for the TUI. If terminal width is too narrow (<80 columns), fall back to single-column with inventory accessible via a toggle key.
- Combat transitions are AI-driven: the AI includes `combat_start` in its response when it determines combat should begin. There is no `/combat` command — combat happens organically through the narrative.
- Crafting is player-initiated via `/craft` because it's a deliberate activity, not a narrative event.
- Items created through crafting have narrative effects only. The AI reads item descriptions during gameplay and interprets their effects contextually. This keeps the system flexible and avoids stat inflation.
- The known_recipes system is a convenience feature — it lets the player see what they've already successfully crafted. It does NOT restrict what they can attempt (no hardcoded recipes).
