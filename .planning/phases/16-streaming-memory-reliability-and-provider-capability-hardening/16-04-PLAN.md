# Plan 16.4: Boot Path Consolidation and Reliability Regressions

## Goal

Collapse duplicated app boot/resume wiring touched by the reliability work and leave Phase 16 with a durable regression harness.

## Tasks

1. Consolidate duplicated story boot, resume, and load wiring into a single initialization path that can honor the refined provider/memory contracts.
2. Remove or isolate low-value duplication introduced by separate “new story”, “resume”, and “load save” setup flows.
3. Extend runtime regressions to cover boot, resume, provider capability changes, and memory recovery edges together.
4. Document the expected startup behavior when providers or mirrors are degraded so future phases do not reintroduce hidden coupling.

## Verification

- story boot/resume/load share one reliable initialization path instead of drifting copies
- provider and memory regressions are covered end-to-end through the runtime entry points
- reliability fixes remain stable under future startup-flow changes
