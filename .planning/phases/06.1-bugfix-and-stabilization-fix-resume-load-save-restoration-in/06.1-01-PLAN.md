# Plan 6.1.1: Bugfix and Stabilization

## Objective

Fix the 6 critical/high/medium findings from the code review to make the game state reliable before adding polish features.

## must_haves

- Resume/load does not restart the story — it resumes from last turn
- Save/load fully restores character state (traits, skills, inventory, recipes)
- Inventory is consistent across prompt, state applicator, persistence, and UI
- Config schema matches documented YAML
- Story metadata (description, genre, tone) persists and displays correctly
- Challenge/achievement fields in narrator response are wired or removed from active contract

## Tasks

### Task 1: Fix resume/load turn corruption

<read_first>
- internal/engine/narrator.go
- internal/engine/session.go
- internal/tui/app.go
- internal/engine/context.go
</read_first>

<action>
1. In narrator.go, add a `ResumeNarration()` method that does NOT call StartNarration (which sends the first-turn prompt). Instead it:
   - Loads the last N chat messages from DB
   - Rebuilds context from those messages
   - Sets the narrator as "ready for input" without calling the AI
   - Restores world.CurrentTurn from DB (not session line count)

2. In session.go, `NewGameSession` should check for an existing active session for this story and RESUME it (not create a new one). Add `ResumeOrCreate` logic.

3. In app.go, when entering narrative from "Load Story", call `ResumeNarration()` instead of `StartNarration()`. Only call `StartNarration()` for brand new stories.

4. Ensure world.CurrentTurn is loaded from world_state DB on resume, not reset.
</action>

<acceptance_criteria>
- narrator.go contains func `ResumeNarration`
- app.go calls ResumeNarration for loaded stories, StartNarration only for new ones
- session.go has resume logic that doesn't create duplicate sessions
- world.CurrentTurn is loaded from DB on resume
</acceptance_criteria>
