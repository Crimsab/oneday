## Tasks

### Task 1: Achievement popup auto-dismiss timer
**File:** `internal/tui/components/achievement_popup.go`
**Action:** Ensure the auto-dismiss timer (5 seconds) is correctly implemented using `tea.Tick`:
1. When `Show()` is called, store a `showTime` and return a `tea.Tick(5*time.Second, ...)` command from the next `Update` cycle
2. Define `achievementTimeoutMsg` as the tick message type
3. In `Update`, handle the timeout: if the popup is still visible and the timeout matches, auto-dismiss
4. Edge case: if user dismisses manually before timeout, the late timeout msg should be a no-op (check visibility or use a generation counter)

**Verify:** Popup auto-dismisses after 5 seconds without interaction. Manual dismiss before timeout works. Late timeout after manual dismiss does not cause issues.

### Task 2: Mood transition smoothness
**File:** `internal/tui/views/narrative.go`
**Action:** Ensure mood transitions don't cause visual jarring:
1. When mood is empty or unknown, fall back to `"neutral"` which uses the default theme palette (warm gold from theme.go)
2. Add `"neutral"` to the `MoodPalettes` map using the current default colors (Primary, Secondary, etc.)
3. On `ResumeNarration`, initialize `currentMood` from the returned response's mood field
4. Ensure the first render after story load already has the correct mood applied (not a flash of default then switch)

**Verify:** Load an existing story — mood coloring is correct from the first frame. Unknown mood strings don't cause panics.

### Task 3: Achievement popup rendering priority
**File:** `internal/tui/views/narrative.go`
**Action:** Handle the case where both an overlay (e.g., `/stats`, `/inventory`) and an achievement popup could be active simultaneously:
1. Achievement popup takes rendering priority over overlay (it's brief and important)
2. If overlay is visible when achievement fires, queue the achievement popup — show it after overlay dismisses
3. Add `pendingAchievement *storage.Achievement` field to queue one achievement
4. On `OverlayDismissedMsg`, check `pendingAchievement` and show popup if pending

Also handle the inverse: if achievement popup is visible and user types `/stats`, the command should be ignored until popup dismisses (already handled by the popup consuming all keys, but verify).

**Verify:** Open `/stats` overlay, trigger an achievement (e.g., via a turn that awards one) — achievement shows after overlay closes. No visual glitch.

### Task 4: Challenge + achievement interaction
**File:** `internal/tui/views/narrative.go`
**Action:** When a turn returns BOTH a challenge AND an achievement:
1. The challenge view takes priority (it requires player interaction)
2. The achievement popup shows AFTER the challenge resolves and the challenge result is processed
3. Store the achievement in `pendingAchievement` when a challenge is also present
4. After `ChallengeCompleteMsg` is processed and the follow-up AI response comes back, show the pending achievement popup

**Verify:** AI returns a turn with both a dice roll challenge and an achievement — challenge resolves first, then achievement popup appears.

### Task 5: Polish achievement display in /achievements command
**File:** `internal/engine/journal.go` (FormatAchievementsView)
**Action:** Enhance the achievement list formatting:
1. Add rarity-specific emoji/symbol prefixes:
   - common: `[*]`
   - uncommon: `[**]`
   - rare: `[***]`
   - epic: `[****]`
   - legendary: `[*****]`
2. Group achievements by category with category headers
3. Show total count and rarity distribution summary at the bottom
4. Format: `[***] "Achievement Name" — Description (rare, exploration)`

**Verify:** `/achievements` command shows nicely formatted list with rarity indicators and category grouping.

### Task 6: Narrator prompt achievement format alignment
**File:** `internal/ai/prompts/narrator.go`
**Action:** Final review and alignment of the achievement section in the narrator system prompt:
1. Ensure the JSON format example shows `"achievement_earned": null` (not `"achievements": []`)
2. Ensure the rules section is concise but complete (don't bloat the system prompt — it's already large)
3. The previously earned achievements list passed via context builder should be formatted as:
   ```
   ## Previously Earned Achievements (do NOT repeat these)
   - "Achievement Name 1" (category)
   - "Achievement Name 2" (category)
   ```
4. If no achievements earned yet, omit the section entirely (don't waste tokens)

**Verify:** Inspect the assembled prompt (add temporary debug logging or breakpoint). Achievement rules present, earned list present, format correct.

### Task 7: Mood palette edge cases and defaults
**File:** `internal/tui/theme/mood.go`
**Action:** Handle edge cases:
1. Add palette for mood values the AI might use beyond the defined set: `"calm"` (map to peaceful), `"horror"` (map to dark), `"hopeful"` (map to lighthearted), `"combat"` (map to tense), `"sad"` (map to dark)
2. Add mood aliases map:
   ```go
   var MoodAliases = map[string]string{
       "calm": "peaceful", "horror": "dark", "hopeful": "lighthearted",
       "combat": "tense", "sad": "dark", "angry": "dramatic",
       "cheerful": "lighthearted", "suspenseful": "mysterious",
       "melancholy": "dark", "triumphant": "epic",
   }
   ```
3. `GetMoodPalette` should check aliases before falling back to default
4. Default palette (for unknown moods) should match the current warm gold theme

**Verify:** Pass various mood strings including aliases and unknowns — all return valid palettes. No panics.

### Task 8: End-to-end game loop verification
**Action:** Manual play-through validation:
1. Create a new story, play through 10+ turns
2. Verify mood theming changes are visible (border colors shift with mood)
3. Play aggressively to trigger an achievement (e.g., creative solution, first combat win)
4. Verify achievement popup appears with correct rarity color
5. Verify `/achievements` shows the earned achievement
6. Save and load the story — achievements persist, mood is correct on resume
7. Verify no regression in:
   - Combat flow (challenges, dice rolls)
   - Crafting flow
   - `/narrator` command
   - `/stats`, `/inventory`, `/map`, `/journal` overlays
   - Autosave

**Verify:** Full game loop works without errors. All 6 requirements (ACH-01 through ACH-04, TUI-08, TUI-09) satisfied.
