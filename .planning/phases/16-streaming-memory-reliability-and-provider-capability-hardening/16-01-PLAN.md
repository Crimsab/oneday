# Plan 16.1: Unified Structured Request Path

## Goal

Bring sync and streaming AI request construction onto the same structured-output contract so provider quirks and fallback behavior no longer diverge by code path.

## Tasks

1. Audit the current `Complete()` and `Stream()` request-building paths for differences in schema guards, plugin injection, provider hints, and retry conditions.
2. Extract a shared request-construction layer for OpenAI-compatible providers that can be used by both sync and streaming calls without losing stream-specific flags.
3. Ensure structured-output safety features such as response-format fallback, provider parameter requirements, and compatible plugin hints behave consistently across both paths.
4. Add focused tests for providers that accept structured sync requests but reject structured streaming requests.

## Verification

- sync and streaming requests carry the same structured-response guards where supported
- provider-specific fallbacks no longer depend on whether the caller used sync or stream mode
- structured-stream regressions are covered by tests instead of manual provider trial and error
