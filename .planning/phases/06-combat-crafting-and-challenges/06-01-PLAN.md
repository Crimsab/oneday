# Plan 6.1: Challenge Engine + Combat Engine Core

## Objective

Build the mechanical foundations for challenges and combat. The challenge engine handles dice rolls, stat checks, item/skill/relationship checks, and mini-game logic. The combat engine manages the turn-based loop, enemy stat generation, damage calculation, and combat resolution — all in Go code, never delegated to AI. AI proposes situations and narrates results; the engine decides outcomes.

## Key Decisions

- **Dice rolls in engine, not AI**: The `d100 + modifiers vs difficulty` formula runs in Go. AI sends challenge specifications in its response; engine executes them deterministically.
- **Enemy stats generated by AI, validated by engine**: AI proposes enemy stats (HP, attack, defense, behavior pattern) in a structured JSON block. Engine validates ranges and clamps unreasonable values.
- **Damage formula**: `player_damage = weapon_base + attribute_bonus + d20_roll` and `enemy_damage = enemy_power + d20_roll - player_defense`. Clamped to minimum 0.
- **Combat is a state machine**: States are `combat_start`, `player_turn`, `enemy_turn`, `combat_end`. The narrator drives transitions.
- **Mini-games are self-contained**: Each mini-game (RPS, memory, quick-time, riddle) has its own resolver. They produce a pass/fail result that feeds back into the narrative.
- **Challenge type detection**: AI includes a `"challenge"` field in NarrativeResponse. Engine parses it and executes before letting AI narrate the outcome.

## Verification

- [ ] `StatCheck` resolves: player stat >= difficulty → pass, otherwise fail
- [ ] `DiceRoll` resolves: d100 + sum(modifiers) >= difficulty → pass
- [ ] `ItemCheck` resolves: item present in inventory → pass
- [ ] `SkillCheck` resolves: skill exists (and optionally level >= threshold) → pass
- [ ] `RelationshipCheck` resolves: NPC disposition >= threshold → pass
- [ ] RPS mini-game: player choice vs AI choice → win/lose/draw
- [ ] Memory sequence mini-game: generates sequence, validates player replay
- [ ] Quick-time mini-game: returns pass/fail based on time limit
- [ ] Riddle mini-game: AI provides riddle+answer, engine checks player answer
- [ ] Combat turn loop: player turn → engine applies damage → enemy turn → engine applies damage → repeat
- [ ] Enemy generation: AI response parsed into EnemyStats struct with validation
- [ ] Player damage calculated correctly with formula
- [ ] Enemy damage calculated correctly with defense reduction
- [ ] HP tracking works for both player and enemy, clamped to 0
- [ ] Combat ends when enemy HP <= 0 (victory) or player HP <= 0 (defeat)
- [ ] Defeat outcome is AI-decided (death, capture, rescue, retreat)
- [ ] Combat sub-session JSONL created and written to
- [ ] Combat summary written to main narrative after resolution

    db *storage.DB,
    storyID string,

**Resolution logic per type:**

1. **stat_check**: Parse `char.StatsJSON`, navigate to `attributes[spec.Stat]`. Compare value >= `spec.Difficulty`. Result detail: `"STR 5 vs difficulty 8 → FAIL"`.

2. **dice_roll**: Roll `rand.Intn(100) + 1` (d100). Sum all `spec.Modifiers[i].Value`. Total = roll + sum(modifiers). Compare total >= `spec.Difficulty`. Result includes raw roll, total, difficulty, and all modifiers for TUI display.

3. **item_check**: Parse `char.StatsJSON` → `inventory.backpack`. Search for `spec.Item` (case-insensitive substring match). Pass if found.

4. **skill_check**: Parse `char.StatsJSON` → `skills[spec.Skill]`. Pass if skill exists. If `spec.SkillLevel > 0`, also check `skill.level >= spec.SkillLevel`.

5. **relationship_check**: Call `db.GetNPCByName(storyID, spec.NPCName)`. Pass if NPC exists and `npc.Disposition >= spec.Disposition`.

6. **mini_game**: Delegate to the mini-game engine (Task 3). This is a placeholder that returns an error saying "mini-game requires TUI interaction" — the actual mini-game resolution happens in the TUI layer with callbacks.

Helper functions:
- `getStatValue(statsJSON string, path string) (float64, error)` — navigates nested JSON by dot-separated path (e.g., `"attributes.str"`)
- `hasItem(statsJSON string, itemName string) bool`
- `getSkillLevel(statsJSON string, skillName string) (int, bool)`

Add `RollD100()`, `RollD20()` helper functions (thin wrappers around `rand.Intn`) for testability — they can be replaced with deterministic functions in tests.

// RiddleChallenge represents a riddle challenge.
type RiddleChallenge struct {
    Riddle string // the riddle text (from AI)
    Answer string // the correct answer (from AI, hidden from player)
}

// NewRiddleChallenge creates a riddle challenge from AI spec.

**RPS logic:**
- AI choice: `rand.Intn(3)` → rock/paper/scissors
- Standard win matrix: rock > scissors, scissors > paper, paper > rock

**Memory logic:**
- Compare player sequence element-by-element against stored sequence
- All must match for pass. Detail shows how many correct.

**QuickTime logic:**
- Check `responseTime.Sub(qtc.StartTime) <= qtc.TimeLimit`
- Pass if within limit, fail if over

**Riddle logic:**
- Normalize both answers: `strings.TrimSpace(strings.ToLower(...))`
- Pass if equal. Could also accept contains-match for partial credit.

**ValidateEnemy** clamps:
- HP: 1-999, Attack: 0-50, Defense: 0-30
- If Behavior is empty, default to "aggressive"

**NewCombatEngine:**
1. Validate enemy stats
2. Open sub-session via `narrator.session.OpenSubSession("combat")`
3. Read player's current HP from `narrator.character.StatsJSON` → `vitals.hp.current` and `vitals.hp.max`
4. Initialize CombatState with turn=1, phase="player_turn"
5. Return engine

**Core methods:**

```go
// PlayerAction sends the player's combat action to AI and processes the turn.
// action can be an attack choice, free text (talk, flee, creative), etc.
// Returns the AI narrative response for this combat turn.
func (ce *CombatEngine) PlayerAction(ctx context.Context, action string) (*CombatTurnResult, error)

// CombatTurnResult contains everything the TUI needs after a combat turn.
type CombatTurnResult struct {
    Narrative     string
    Choices       []Choice
    PlayerDamage  int    // damage dealt TO player this turn (0 if player's turn only)
    EnemyDamage   int    // damage dealt TO enemy this turn
    PlayerHP      int
    EnemyHP       int
    CombatOver    bool
    Victory       bool
    DefeatOutcome string // only set if CombatOver && !Victory
    Summary       string // only set if CombatOver
    Mood          string
}
```

**PlayerAction flow:**
1. Build combat context: system prompt (combat-specific) + combat state + recent combat chat + player action
2. Call AI for narrative response
3. Parse AI response (same NarrativeResponse format but in combat context)
4. **Engine calculates damage:**
   - Player attacks: `base_damage = getWeaponBase(char) + getAttributeBonus(char, "str") + RollD20()`
   - Apply enemy defense: `actual_damage = max(0, base_damage - enemy.Defense)`
   - Update enemy HP
5. **Enemy counter-attacks** (based on behavior pattern):
   - `enemy_damage = enemy.Attack + RollD20() - getPlayerDefense(char)`
   - Clamp to >= 0
   - Update player HP (both in CombatState and character stats)
6. Check win/lose conditions:
   - Enemy HP <= 0 → victory. AI narrates victory.
   - Player HP <= 0 → defeat. AI decides outcome (death→reload, capture, rescue, retreat).
7. Log turn to sub-session JSONL
8. If combat over: generate summary, write to main narrative, close sub-session, sync player HP back to character stats

**Helper functions:**
```go
// getWeaponBase checks equipped weapon for a base damage value.
// Returns 1 if no weapon equipped (fist fighting).
func getWeaponBase(char *storage.Character) int

// getAttributeBonus returns the bonus from an attribute (value / 3, rounded down).
func getAttributeBonus(char *storage.Character, attr string) int

// getPlayerDefense returns the player's defense value from armor + endurance bonus.
func getPlayerDefense(char *storage.Character) int

// behaviorModifier adjusts enemy attack based on behavior pattern and turn.
func behaviorModifier(behavior EnemyBehavior, turn int) int
```

**Behavior modifiers:**
- Aggressive: +2 attack always
- Defensive: -2 attack, but if turn is even (counter turn), +4
- Tactical: alternates between +1 and +3 based on turn
- Beast: +3 on turns divisible by 3 (telegraphed big attack), 0 otherwise
- Intelligent: adapts — if player HP is low, +3; if enemy HP is low, -2 (retreating)

```go
// EndCombat finalizes the combat, writes summary to main chat, syncs state.
func (ce *CombatEngine) EndCombat(ctx context.Context) error

// WriteSummaryToMain writes the combat outcome summary to the main narrative JSONL.
func (ce *CombatEngine) WriteSummaryToMain() error
```

## Notes

- The combat engine does NOT render anything — it returns `CombatTurnResult` and the TUI layer (Wave 2 of Phase 6) renders it.
- Mini-game resolution for RPS and riddles can happen entirely in the engine. Memory and quick-time require TUI interaction — the engine provides the challenge spec and a `Check*` function, the TUI handles the user interaction timing.
- The `rand` package is used for dice rolls. For reproducible tests, seed with a fixed value.
- Enemy stats are AI-generated but engine-validated. The AI is instructed to propose reasonable stats; the engine clamps outliers.
- Combat chat uses a separate JSONL file (`combat_1.jsonl`) via the existing `OpenSubSession` mechanism.
- Defeat outcomes are AI-decided to keep the narrative interesting — but death is documented as rare. The engine provides the combat context; the AI picks the most dramatically appropriate outcome.
