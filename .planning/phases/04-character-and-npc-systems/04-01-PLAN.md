# Plan 4.1: Character Growth Engine and NPC Generation/Persistence

## Objective

Build the character progression system (skill XP/leveling, trait assignment, title awards) and the NPC runtime generation/persistence pipeline. After this plan:
- The AI can suggest attribute increases (+1), trait assignments, skill XP gains, and title awards through `state_changes`
- The state applicator validates and applies all character growth changes
- When the AI introduces a new NPC, a structured `new_npc` block in state_changes triggers parsing, validation, and DB persistence
- NPC disposition updates flow through state_changes
- NPC CRUD operations exist in the storage layer
- The narrator system prompt instructs the AI on how to use character growth and NPC generation fields

## must_haves

- State applicator handles `skill_xp` key: adds XP to a skill, creates the skill if new, levels up at thresholds
- State applicator handles `trait_add` key: appends a new trait to the character
- State applicator handles `title_add` key: appends a new title to the character
- State applicator handles `new_npc` key: parses NPC data and persists to DB
- State applicator handles `npc_disposition` key: updates an existing NPC's disposition
- State applicator handles `npc_thoughts` key: appends to NPC's private_thoughts
- NPC CRUD in storage layer (Create, Get by ID, Get by name+story, List by story, Update)
- NPC model fields: LastSeenTurn added to storage model
- NarrativeResponse type extended with `NewNPCs` field for parsed NPC data
- Narrator system prompt updated to teach AI about character growth and NPC generation format
- Character starts with empty traits, empty skills, empty titles (CHAR-01 — already done via InitialStats)
- Skills stored as `map[string]{"level": int, "xp": int}` inside stats_json

Add new cases to `ApplyStateChanges` in `state.go`:

**Case `"trait_add"`**: Value is a string (trait name).
- Parse current traits from stats JSON (key `"traits"`, type `[]string`)
- Check for duplicates (case-insensitive)
- If not duplicate, append the trait
- Also update `char.TraitsJSON` to stay in sync
- Return a StateChange with Description "Gained trait: {name}"

**Case `"title_add"`**: Value is a string (title name).
- Parse current titles from stats JSON (key `"titles"`, type `[]string`)
- Check for duplicates
- If not duplicate, append the title
- Return a StateChange with Description "Earned title: {name}"

**Case `"skill_xp"`**: Value is a map `{"skill": "Lockpicking", "xp": 15}`.
- Parse current skills from stats JSON (key `"skills"`, type `map[string]map[string]int`)
- If skill doesn't exist, create it with `{"level": 1, "xp": 0}`
- Add XP to the skill
- Check level-up: XP threshold = `level * 100`. If xp >= threshold, level++, xp -= threshold
- Return StateChange with Description "Gained 15 XP in Lockpicking" (and "Lockpicking leveled up to 2!" if leveled)

**Case `"skill_learn"`**: Value is a string (skill name). Shorthand for learning a new skill at level 1, 0 XP.
- If skill already exists, no-op
- If new, create with `{"level": 1, "xp": 0}`
- Return StateChange with Description "Learned new skill: {name}"

After handling all new cases, re-marshal stats back to `char.StatsJSON`.
</action>

- `state_changes: {"title_add": "Dragon Slayer"}` adds to titles
- `state_changes: {"skill_xp": {"skill": "Lockpicking", "xp": 50}}` creates or updates skill
- `state_changes: {"skill_learn": "Alchemy"}` creates skill at level 1
- Skill levels up when XP exceeds `level * 100` threshold
- `char.TraitsJSON` is updated when traits change
- `char.StatsJSON` is marshaled back with all changes
- All changes produce `StateChange` entries with descriptive text
</acceptance_criteria>

```go
package engine

// NPCPersonality holds the structured personality of an NPC.
type NPCPersonality struct {
    Traits      []string `json:"traits"`
    SpeechStyle string   `json:"speech_style"`
    Quirks      []string `json:"quirks"`
    Values      []string `json:"values"`
    Fears       []string `json:"fears"`
}

// NPCDesire represents a hidden NPC motivation.
type NPCDesire struct {
    Desire       string `json:"desire"`
    Priority     string `json:"priority"`
    KnownToPlayer bool  `json:"known_to_player"`
}

// NPCData is the AI-generated NPC structure from state_changes.
type NPCData struct {
    Name            string         `json:"name"`
    Role            string         `json:"role"`
    Appearance      string         `json:"appearance"`
    Personality     NPCPersonality `json:"personality"`
    PrivateThoughts []string       `json:"private_thoughts"`
    Desires         []NPCDesire    `json:"desires"`
    Disposition     int            `json:"disposition"`
    CanHelp         bool           `json:"can_help"`
}

// ParseNPCData converts an untyped map (from AI JSON) into a structured NPCData.
func ParseNPCData(raw map[string]interface{}) (*NPCData, error)

// NPCToStorage converts NPCData + metadata into a storage.NPC ready for DB insert.
func NPCToStorage(data *NPCData, storyID string, turn int) (*storage.NPC, error)

// FormatNPCForContext returns a condensed text representation of an NPC
// suitable for injection into the AI context. Includes personality, disposition,
// private thoughts, and desires (all — the AI sees everything).
func FormatNPCForContext(npc *storage.NPC) string

// FormatNPCForPlayer returns a player-visible summary of an NPC (no private thoughts,
// no hidden desires). Used for a potential /npcs command or character sheet relationships.
func FormatNPCForPlayer(npc *storage.NPC) string
```
